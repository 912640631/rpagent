# 独立 RPG 智能体系统

用户已确认整体规格并授权使用 TypeScript 实现；首版已实现，见 RpgAgent/README.md。

## 已确认

- 个人项目，以能运行、能玩为优先，避免过度设计；主 Agent 聚焦叙事。
- 当前仓库新增独立命令行应用，直接复用 NarrativeDice 与 CombatEngine。
- Provider 只是模型通道路由键；配置保存 baseURL、密钥来源、协议类型和默认模型，与 Adapter 实现分开。
- 第一版实现通用 OpenAI Chat Completions API Adapter；兼容服务通常只新增 Provider 配置。
- Adapter 是协议边界，负责厂商字段转换、HTTP、流解析和错误转换；Harness 使用统一 Message、GenerateOptions、StreamChunk。
- 主 Agent 和战斗子 Agent 可分别配置 provider/model，默认共用。
- 主 Agent 通过结构化输入交接一次战斗，只传战斗所需数据，不传完整聊天历史。
- 战斗子 Agent 与 CombatEngine、玩家交互并提供风味描述；每次战斗使用新上下文，不保留跨战斗隐式记忆。
- 子 Agent 返回值须有预算。
- 主 Agent 保留最近一段原始消息，旧历史压为固定结构的叙事续接备忘；它满足原需求的续接信息保留目的，不构成额外游戏状态系统。
- System Prompt、工具定义、权限规则永久保留，不交给摘要模型改写。
- 压缩要求 summary_tokens < original_tokens * 0.5；不满足时二次压缩。
- 自动压缩依据 API 返回的 token 用量产生的上下文压力触发，另支持玩家手动触发；不按轮数触发。
- 支持本地存档和续玩；保存叙事续接备忘、最近原始消息和规则状态。
- 战斗按已完成规则步骤恢复，未完成的模型文本生成可以重试，不做逐 token 恢复。
- 首版沿用现有战斗范围：杰洛特对单只目录怪物，不扩展 CombatEngine。
- 战斗期间主 Agent 暂停，战斗子 Agent 使用同一个 CLI 与玩家交互。
- 玩家意图明确时，子 Agent 转为合法引擎命令直接执行；有歧义时澄清。规则外行动说明限制并给出已有规则支持的选项。
- 引擎决定数值结果，子 Agent 负责解释和风味描述。
- 现有角色规则字段跨战斗延续，由应用投影并传回引擎；摘要不能改写权威规则数值。
- 不引入 NarrativeDice 和 CombatEngine 不支持的冒险状态系统，不新增任务、关系、背包等权威模型，保持主 Agent 的叙事自由度。
- 第一版兼容服务要求支持 Chat Completions 工具调用，默认流式输出；流式缺少 usage 时尝试非流式请求，仍缺失时提示自动压力判断不可用并保留手动压缩。
- 不实现文本模拟工具调用协议。
- 叙事续接备忘固定为三个文本字段：当前局面、继续所需的事实、尚未完成的行动与玩家意图。内容自由书写，不引入任务状态、关系数值或物品管理，不复制权威规则数值。
- Provider 配置模型上下文容量。API 返回的用量达到容量的 75% 时，在下一次模型请求前压缩；另提供 /compact。
- 最近原始消息默认保留约 6,000 tokens；工具调用及结果成组保留，模型容量较小时缩减此预算。
- 压缩输入包含上次备忘和待压缩旧消息；使用同一 token 计数口径验证新摘要严格小于被替换内容的 50%。
- 第一次压缩不达标时二次压缩；再次失败保留原内容。无法容纳下一次请求时暂停生成并提示玩家处理，不无限重试。
- 战斗返回默认最多 1,500 tokens，可配置。返回胜负、参与者最终规则状态、必要后果及短篇风味描述；完整事件保存在引擎存档。
- 返回预算优先删减风味和事件描述，保留恢复叙事必需的规则结果；必要字段本身超预算时明确报错，不静默截断。

## 代码事实

- createAdventureSession 已管理希望、绝望、资源所有权及战斗持久化。
- createBattleHandoff 已提供 start/status/act/settlement 结构化边界。
- 当前战斗规则只支持杰洛特对单只目录怪物；自由文本目标返回 not_evaluated。
- 希望、绝望已有连续性；HP 等角色状态需要应用另行投影并在下一场战斗传入。
- settlement 包含完整事件和交接信息，不能原样作为有预算的子 Agent 返回值。

## 最小运行闭环

1. CLI 加载本地存档、Provider 配置和主 Agent 上下文。
2. 玩家输入交给主 Agent；Adapter 统一处理 Chat Completions 请求、文本流、工具调用与 usage。
3. 主 Agent 在叙事中按需调用 NarrativeDice；进入战斗时只提交结构化战斗所需数据。
4. Harness 暂停主 Agent，以新的战斗子 Agent 上下文接管同一个 CLI；玩家选择与怪物行动通过 CombatEngine 求解。
5. 战斗结束时保存权威规则状态，生成预算内结果；主 Agent 接收结果并继续叙事。
6. 根据 API 用量或玩家手动命令压缩旧历史，永久指令和最近完整消息保持可用。
7. 重启后读取已完成的引擎步骤和上下文存档；未完成的模型输出可以重新生成，恢复不得重复执行已提交的规则操作。

## 实现范围

- 新增独立应用入口、轻量 Harness、通用 Chat Completions Adapter、Provider 配置、主 Agent 与战斗子 Agent、上下文压缩和应用存档。
- 复用现有引擎的结构化交接与持久化接口，不复用旧 DSH 的子会话调度机制；旧 DSH 的 provider='spawn' 与模型 Provider 不是同一概念。
- 不扩展战斗规则，不新增冒险状态系统，不做跨战斗子 Agent 隐式记忆，不做 UI 或通用多 Agent 框架。
- 协议内部表示、文件拆分和具体提示词按上述约束选择最简单的实现；不另行扩大设计访谈。

## 访谈修正

- Q8 拒绝主 Agent 维护新增结构化冒险状态；不得将先前推荐的任务、关系、物品模型当成已接受方案。
- 当前未发现战斗外休息恢复接口。此前 Q6 推荐中的“休息或恢复操作”不应变成新增规则；首版仅沿用引擎已有的状态变化，不通过叙事自动回血。

## 实现记录

- 独立 npm workspace：RpgAgent；根目录 npm run rpg 启动。
- 本地接入文件 api接入.txt 可通过 --init 生成被 Git 忽略的 Provider 配置；local 和 deepseek 共用 Chat Completions Adapter。
- 为避免重放已提交规则步骤，应用存档保存执行前工具日志，恢复时核对权威引擎版本；规则存档与应用存档须一起保留。
- 本地预算统一使用 cl100k_base tokenizer；兼容服务实际 tokenizer 可能不同。自动 token 压力仍以 API usage 为依据。
- 不支持流式的 Provider 可配置 stream: false。流式缺少 usage 时改用后续非流式请求获取，不为同一已完成生成额外重放请求。
- 真实 local / gpt-6.1-sol 已验证模型请求及 usage、叙事掷骰工具调用、战斗交接和等待玩家；DeepSeek 已配置但未实测远程通道。
