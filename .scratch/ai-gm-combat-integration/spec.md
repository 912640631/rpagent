# AI-GM 叙事与多人战斗衔接

## Problem Statement

玩家希望扮演杰洛特，在 AI 每局即兴编写的猎魔人风格支线中自由行动。现有玩法由主 GM 用 NarrativeDice 判定并持续叙事；提供的轨迹包含潜入、单体交战、叶奈法协作、群战、交涉与关系剧情，体验已可游玩，但所有战斗仍靠主 GM 的叙事和叙事骰完成。

CombatEngine 已能持久化战斗会话并产出结构化事件，但目前仅支持杰洛特对一只预置怪物，且其绝望规则与 NarrativeDice 不一致。dsh 能让玩家在 Web 或 Desktop 的持续运行子会话里直接与战斗子 agent 对话，但默认每次子会话回复都会唤醒主 GM。直接拼接现有组件会让主 GM 被普通战斗回合打断，也无法忠实结算多对多、临场敌人和同伴参与的战斗。

## Solution

主 GM 继续即兴创作剧情，并在实际进入交战时发起一个持续运行的战斗子会话。它只需提交场景、参战者、目标、已确立的剧情事实、敌人强弱意图和共享资源的状态；战斗子 agent 生成并校验所需战斗数据，与玩家直接互动，驱动 CombatEngine 结算，直到战斗结束。玩家只操作杰洛特，队友与敌人自行行动。主 GM 仅在需要决定尚未由规则确定的重大剧情变化、战斗结束或运行出错时收到通知。

叙事与战斗共用持久化的希望、绝望和冒险事实。战斗期间所有有后果的行动由 CombatEngine 判定；战后向主 GM 返回可核对的结构化结算和简短叙事摘要，由主 GM 接续故事。新开一局才重置状态，同一局可中断后恢复。

## User Stories

1. 作为玩家，我希望新开一局时由 AI 创作新的杰洛特支线，以便每次游玩都有不同的故事。
2. 作为玩家，我希望在剧情中用自然语言描述杰洛特的行动，以便保留现有轨迹里的自由扮演方式。
3. 作为玩家，我希望探查、交涉及一般环境危机继续由 NarrativeDice 判定，以便非战斗场景维持熟悉的节奏。
4. 作为玩家，我希望实际进入交战时清楚知道已切换到战斗规则，以便理解接下来的行动怎样结算。
5. 作为玩家，我希望能从主剧情打开可继续对话的战斗子会话，以便直接在其中游玩而不等主 GM 逐回合转述。
6. 作为玩家，我希望每次杰洛特能行动时自行选择目标、剑术、法印、道具或其他战术，以便保持对角色的控制。
7. 作为玩家，我希望用自然语言提出配合、佯攻、利用地形等临场战术，以便战斗不局限于固定菜单。
8. 作为玩家，我希望临场战术经过合法性检查与掷骰结算，以便叙事不能绕过规则直接宣布成功。
9. 作为玩家，我希望可以向叶奈法等队友提出配合意图，以便共同作战而不必逐个操作队友。
10. 作为玩家，我希望队友按自身能力和局势行动，以便多人战斗在我只控制杰洛特时仍能持续推进。
11. 作为玩家，我希望面对多名敌人与多名友方的战场，以便体验类似轨迹里的群战和协作。
12. 作为玩家，我希望遇到既有怪物，也可能遇到 AI 临场创造的敌人，以便故事不被怪物目录限制。
13. 作为玩家，我希望临场敌人的战斗能力在开战前确定并保存，以便战斗中不会因剧情需要被暗改。
14. 作为玩家，我希望每次杰洛特行动后看到关键骰值、成败、目标状态、希望和绝望变化，以便理解战况。
15. 作为玩家，我希望队友和敌人的连续行动被清楚但紧凑地叙述，以便知道局势又能尽快作出下一次选择。
16. 作为玩家，我希望在战斗中花费 2 希望获得判定 +3，并能与环境优势并用，以便两种规则的资源预期一致。
17. 作为玩家，我希望杰洛特在战斗中掷出希望面较高或双骰相等时也能获得希望，以便资源规则不随场景切换。
18. 作为玩家，我希望战斗可以围绕救援、保护、撤退、俘获或逼退敌人结束，以便每场冲突不必靠击杀收尾。
19. 作为玩家，我希望战斗中可改为撤退、劝降或俘获，以便能根据局势改变计划。
20. 作为玩家，我希望战斗结果真实生效，包括受伤、失能、死亡和敌人逃脱，以便选择与骰子都具有后果。
21. 作为玩家，我希望战后自动回到主 GM 的叙事，以便结果自然成为后续故事的一部分。
22. 作为玩家，我希望同一局的伤势、物品、关系、希望和绝望跨支线保留，以便冒险具有连续性。
23. 作为玩家，我希望中断的战斗能从最后已保存的状态继续，以便重启后不必重打一场。
24. 作为主 GM，我希望自行判断临场敌人的叙事强弱并交付战斗意图，以便继续自由编纂剧情，而不受预设强度表限制。
25. 作为主 GM，我希望只提交开战场景、参与者、目标和已有事实，以便无须亲自填写每个角色的战斗数值。
26. 作为主 GM，我希望战斗子 agent 自行生成并校验临场参战者数据，以便开战工作不回流给我。
27. 作为主 GM，我希望普通战斗回合不唤醒我，以便我只处理叙事责任范围内的事情。
28. 作为主 GM，我希望尚未由引擎决定的重大 NPC 命运、任务目标变化或新主线事实在发生前交给我决定，以便维持剧情一致性。
29. 作为主 GM，我希望引擎已经结算的伤亡立即告知我且不可改写，以便机械结果始终可信。
30. 作为主 GM，我希望战斗结束时收到结构化结算和简短摘要，以便不阅读子会话完整记录也能继续叙事。
31. 作为主 GM，我希望结算列出胜负、存活者、伤势、资源、物品变化、目标状态和待续场景，以便后续剧情不遗漏重要事实。
32. 作为战斗子 agent，我希望掌握独立且可恢复的战斗会话，以便直接与玩家多轮互动。
33. 作为战斗子 agent，我希望使用带参战者 ID 和目标 ID 的行动与事件，以便正确结算多对多行动。
34. 作为战斗子 agent，我希望杰洛特行动用二元骰，队友与敌人用 d20，以便队友不获得或消费杰洛特的希望和绝望。
35. 作为战斗子 agent，我希望在需要主 GM 决定的重大事件处暂停，以便不自行创造不可逆的主线事实。
36. 作为战斗子 agent，我希望主 GM 暂时不可达时保存待决事件并等待，以便不猜测决定或重复结算。
37. 作为维护者，我希望逐个子会话启用或禁用普通结算通知，以便战斗会话安静运行而其他子会话保留原有行为。
38. 作为维护者，我希望通知策略在子会话恢复后仍然生效，以便重启不会意外唤醒主 GM。
39. 作为维护者，我希望重复提交或过期行动无法重复改变战斗与共享资源，以便故障恢复时维持状态一致。
40. 作为维护者，我希望能用可复现的验收场景覆盖既有单怪、自创怪、队友协作和多敌群战，以便确认整条玩法链路可用。

## Implementation Decisions

- 增加一个冒险与战斗的协调边界，负责开战交接、共享资源、待决重大事件和战后结算。主 GM 只调用开战交接并处理重大事件与最终结果；普通回合完全留在子会话。
- 新局由主 GM 自由创作，不使用固定剧情脚本。主 GM 自行判断敌人的叙事强弱；战斗子 agent 依据交接信息生成符合数据结构的战斗配置并在首回合前锁定。只做结构与规则合法性校验，不设预先规定的怪物强度表。
- 将战斗状态从固定的杰洛特与单怪物改为带唯一 ID、阵营、角色类别和目标 ID 的参战者集合。行动、效果、持续状态、事件、主动权与结局均按参战者和战斗目标表达，不把人数写成规则上限。
- 保留现有战斗规则中仍适用的暴击、伤害、状态、法印、道具与连续行动语义；扩展为玩家仅在杰洛特可行动或必须作出濒死等关键选择时输入。队友和敌人由战斗子 agent 驱动，连续行动合并为清楚的玩家反馈。
- 杰洛特的判定使用希望与绝望各一颗 d12。两骰相等自动暴击成功；其余按难度和高骰归入成功希望、成功绝望、失败希望、失败绝望。希望面较高或暴击获得 1 希望；绝望面较高获得 1 绝望，不论行动成功或失败。希望上限 6、绝望上限 12，新局初始分别为 2 和 0。
- 杰洛特可在掷骰前消费 2 希望获得固定 +3；这与现有环境优势或劣势的骰子效果分别表示，可以叠加。既有暴击伤害和连续行动效果继续生效。怪物招式和强化使用同一 GM 绝望池，按其招式费用消费。
- 队友与敌人的判定使用各自属性加 d20，对固定难度或目标防御结算。队友不使用二元骰，不获得或花费希望与绝望。敌方可按战斗规则消费 GM 绝望，但其 d20 不自行产出希望或绝望。
- 战斗期间 NarrativeDice 不再掷骰；战斗外继续由 NarrativeDice 判定。希望和绝望由同一个冒险级状态账本持有，战斗与叙事通过明确的所有权交接读写，避免两个组件同时修改各自副本。
- 自由战术动作由子 agent 转换为可校验的目标、消耗、难度及效果，再由引擎结算。无法合法转换时，子 agent 说明限制或请玩家调整行动；不能靠文字绕过结算。
- 开战交接包含场景、已确定事实、参战者、目标、环境、可预见的增援或风险以及资源版本。战斗中可按玩家行动改变撤退、劝降、俘获等目标；场景已埋下的增援可按规则出现。凭空增加会改变任务的新角色或事实须交主 GM。
- 战斗结束条件包含消灭或逼退威胁、完成保护或救援、撤退、投降、俘获、角色失能或死亡，以及既有行动上限的明确处理。引擎结算的伤亡不可由主 GM 推翻。
- 未由引擎决定的不可逆 NPC 命运、任务目标变化和新主线事实以待决事件暂停战斗，由主 GM 决定后续叙事约束；已由引擎结算的死亡立即上报，由主 GM 处理剧情后果。
- 战斗子会话使用 dsh Web 或 Desktop 已有的持续运行子会话交互。玩家在子会话直接发消息；现成纯终端入口不作为首版玩家交互方式。
- dsh 增加逐子会话、可持久化的普通结算通知策略，支持启用和禁用。默认保留现有逐次通知；战斗子会话选择安静模式，普通回合不唤醒主 GM。重大事件、终局和错误走明确的通知通道，子 agent 的回报提示也须遵守此策略，避免重复上报。
- 战后返回结构化且可与引擎最终状态核对的结果，包括战斗 ID、结果、目标状态、各参战者生死与伤势、持续效果、资源与物品变化、关键事件和待续场景，另附简短叙事摘要。主 GM 据此继续故事，不重新掷骰或改写结果。
- 冒险状态和战斗状态持久化，行动采用版本或等效幂等约束。恢复时以已提交的最后一步为准；待决重大事件在主 GM 不可达时保持暂停。若玩家输入尚未写入持久记录就发生故障，允许提示玩家重发，但不得重复应用已提交的行动。
- 同一局跨支线保留已确立的剧情事实、关系、伤势、装备、希望和绝望；只有明确新开一局才重置。剧情文本不能成为唯一的资源或战斗真相来源。

## Testing Decisions

- 以“主 GM 发起 → 玩家在持续运行子会话交战 → 主 GM 接收可核对结果并续写”为主要验收缝。通过可控的模型回复和掷骰运行完整玩家路径，断言外部可见消息、状态与结果；不测试内部函数调用顺序或叙事措辞。
- 在战斗会话公开接口层验证多参战者、显式目标、自动队友与敌方行动、自由战术动作、改换目标、保护、撤退、俘获、失能和死亡。沿用现有战斗 session 测试中的固定种子、跨进程续战和过期 revision 拒绝方式。
- 在资源交接层验证 NarrativeDice 与 CombatEngine 共享的希望和绝望：五种杰洛特判定结果、暴击、上限、花费、环境优势叠加、敌方花费，以及队友 d20 不产生资源。沿用现有 NarrativeDice 固定骰子和 CLI 持久化测试风格。
- 在子会话与通知的用户可观察边界验证默认通知、战斗安静模式、重大事件、终局、错误、冷恢复和主 GM 暂不可达。沿用 dsh 现有的持续运行子会话、结算通知及客户端会话交互测试。
- 使用三个已确认的验收遭遇：杰洛特对目录中的单怪、对临场生成的敌人，以及杰洛特与叶奈法面对约七只水鬼。至少一个遭遇以保护或撤离目标结束，不依赖清空敌人。
- 验证中断恢复和重复提交不会重复扣希望、加绝望、消耗道具或结算伤害。战后结果必须能从持久化战斗状态重新核对。
- 保留一次真实 dsh Web 或 Desktop 的人工游玩检查，确认玩家能进入子会话、直接互动并回到主剧情；自动化测试承担规则和契约的回归保障。

## Out of Scope

- 固定支线脚本、每局相同的剧情或由引擎代替主 GM 编写整段故事。
- 首版纯终端的子会话聊天入口或跨独立 dsh 进程的父子消息桥。
- 玩家逐个控制全部友方角色，或多名真人玩家分别控制不同角色。
- 预设所有自创怪物的强度等级表；敌人的叙事强弱由主 GM 判断。
- 以真实模型生成的具体文风、剧情桥段或台词作为自动化断言。
- 在主 GM 不可达时由战斗子 agent 自行决定待决重大剧情事件。

## Further Notes

- 用户提供的轨迹有 19 个回合；战斗与险情使用 NarrativeDice，并没有调用 CombatEngine 或子 agent。它证明了自由叙事的目标体验，也提供了单体、协作和群战的验收样例。
- 当前 dsh Web 与 Desktop 已支持玩家直接进入持续运行子会话；普通子会话每次空闲结算都会通知父会话。安静模式需要修改 dsh 的子会话创建、持久化、结算通知和子 agent 回报提示，不能仅靠现有生命周期观察事件实现。
- 当前战斗引擎的参战者、目标和主动权都以固定双方表示，且没有希望资源；本功能是规则与状态模型扩展，不只是添加一段交接提示词。
- 项目目前没有领域术语表或相关 ADR。实施中若新增稳定术语或作出超出本规格的架构选择，应同步记录领域文档或决策记录。
