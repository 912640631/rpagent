# 本地 React RPG 前端

Status: ready-for-agent

## Problem Statement

项目目前通过本机命令行运行完整 RPG Agent。玩家需要在对话之外查看角色和战斗状态，开发者需要方便地切换模型、调整推理强度和上下文设置、观察工具执行并测试角色状态。现有入口不能提供统一的可视化体验，也没有为后续战斗 UI、动画和音频建立表现入口。

玩家还需要在冒险与战斗中途保存和读取进度。AI-RP 的一次玩家输入可能包含多个模型请求与规则操作，仅保存规则状态或把聊天文本当作存档，无法恢复 Agent 当时掌握的信息和一致的游戏现场。模型上下文压缩也不能成为玩家故事记录丢失的原因。

## Solution

提供由一个命令启动的本地 React 浏览器前端和本地服务，接入完整 RPG Agent。以玩家体验为主，同时提供适度的调试控制台。采用类似 Codex 的左侧冒险列表、中间对话、右侧状态和底部控制台布局，视觉为浅色古籍 / TRPG 风格。

玩家通过自然语言推进故事和战斗，查看角色卡与真实规则状态，并看到短暂、不阻塞后台的立体骰子动画。希望骰和绝望骰明显不同。第一版提供多个本地冒险、自动续玩、完整故事记录，以及在 AI-RP 安全节点生成的命名手动存档。

设置支持独立调整主 Agent 与战斗子 Agent 的模型、推理强度和风格指令，保留默认提示词备份并可恢复；只限制单次请求的最大输出 token，主 Agent 压缩触发比例可调，战斗子 Agent 不压缩，工具循环上限为 48 步。

## User Stories

1. 作为本机玩家，我希望用一个命令启动网页和本地服务，以便直接开始冒险。
2. 作为玩家，我希望界面接入完整 RPG Agent，以便同时体验叙事和战斗。
3. 作为玩家，我希望创建多个本地冒险，以便分别保存不同游玩进度。
4. 作为玩家，我希望从左侧列表选择冒险，以便找到并继续对应故事。
5. 作为玩家，我希望在中间阅读故事并输入自然语言行动，以便连续推进冒险。
6. 作为玩家，我希望看到流式回复和当前执行状态，以便知道系统正在处理什么。
7. 作为玩家，我希望在右侧查看角色卡和战斗状态，以便理解当前局面。
8. 作为玩家，我希望查看希望、绝望、HP、护甲、法印点、毒性及已有状态和药剂，以便决定下一步行动。
9. 作为玩家，我希望收起右侧状态栏和底部控制台，以便腾出故事阅读空间。
10. 作为玩家，我希望界面采用浅色羊皮纸、墨色正文和古籍式标题，以便获得 TRPG 氛围且适合长篇阅读。

## Implementation Decisions

### 应用边界与事件

- React 应用负责交互、视觉、状态展示和骰子动画；本地服务负责模型连接、规则状态、存档与冒险生命周期。
- 以现有 Harness 为应用接入边界，复用玩家输入、战斗交接、叙事续接和异常恢复，不另建一套游戏求解流程。
- 增加结构化消息边界、模型请求状态、工具结果与规则事件。服务公开冒险操作和状态/事件读取，保证事件顺序与重连去重；具体传输协议留给实现选择。
- 完整玩家可见故事及必要事件位置独立持久化，不依赖会压缩或清理的模型历史。
- 同一冒险的玩家输入、设置应用、角色修改与存读档串行协调，保留现有单写入者约束。
- 新增服务入口与原 CLI 共用核心流程；具体兼容与迁移策略须结合待确认的原有实现修改范围处理。

### Agent、配置与提示词

- 主 Agent 负责叙事；战斗子 Agent 每次战斗交接以新上下文开始，本场保留多轮交互，结束后清理，不保留跨战斗隐式记忆。
- 压缩只作用主 Agent，触发比例默认 75% 并可调，保留现有叙事续接备忘及近期内容机制；战斗子 Agent 不新增压缩。
- 分别配置两个 Agent 的 Provider、模型、推理强度和风格指令；上下文容量按实际模型配置。
- 提供最大输出 token、近期内容保留预算和战斗结果内容预算。不增加输入输出合计请求预算或整轮 token 预算。
- 不启用 temperature / top_p。额外请求字段不能覆盖模型、消息、工具等程序维护的协议字段，推理字段按服务能力处理。
- 配置保留当前冒险，从下一请求生效；正在执行的请求保留启动时的配置。执行状态与生效状态对玩家可见。
- 风格指令可编辑；默认提示词独立备份、可恢复；工具协议、规则约束和战斗交接由程序维护；控制台可查看最终有效提示词。
- 保留 120 秒单请求超时，工具循环上限改为 48 步，不新增整轮消耗限制。
- 密钥留在本地服务配置中，支持直接配置或环境变量来源，不进入故事记录、事件输出或手动快照配置副本。

### 调试与规则状态

- 非战斗、无请求执行时允许修改现有规则支持的角色字段，如 HP、护甲、法印点、毒性、希望/绝望及已有状态/药剂。
- 编辑通过规则层验证、受锁和 revision 保护的接口提交，不能绕过上限、非法状态或权威资源账本。
- 指定怪物测试创建独立测试存档，保留原冒险。
- 第一版不允许战斗中直接修改角色数值，不提供规则公式或怪物目录编辑器。

### 骰子与未来表现

- 规则引擎唯一决定实际随机结果，动画不消费规则随机数或重新提交规则操作。
- 通用骰子动画的骰面/随机范围须与实际判定一致；真实逐骰结果驱动落点，只有汇总值时展示真实汇总，不将模拟落点标作真实骰值。
- 希望骰与绝望骰以不同颜色、纹样与文字标记区分；具体色彩以浅色古籍主题可读性为准。
- 动画短暂播放、不阻塞后台，相关结果按事件顺序展示；支持关闭、跳过、时长和减少动态效果，不提供手动重播。
- 历史恢复不触发旧动画。服务区分历史恢复与新执行事件。
- 部分伤害和修正骰信息不能可靠从已有汇总结果推导；必要时增加可选骰子类型/范围记录，不改变数值规则与随机数消耗顺序，并遵循原有实现修改确认要求。

### AI-RP 存读档

- 自动续玩沿用内部步骤的持久化及 pending/revision 恢复，避免重复执行已提交行动。
- 手动存档只在系统等待玩家输入时生成，含战斗行动和决策等待节点。
- 处理中请求保存、读档或切换冒险，排队等待当前处理完成；不能在工具执行或流式生成中间捕获不一致快照。
- 完整快照包含配套应用上下文、权威规则状态、随机数状态、叙事续接备忘、本场 Agent 上下文、故事记录和必要事件位置。
- 在同一串行边界捕获配套状态，不把单个规则文件或只读战斗记录当作完整快照。
- 读档前自动备份当前进度；读取恢复游戏、Agent 记忆和对应故事时刻，回退保存时刻之后的可见记录。
- 读档保留当前模型、推理强度与自定义风格指令，保存时的非敏感配置仅供对照；随机数恢复不保证模型随后生成相同故事。
- 刷新与页面断开不终止后台处理；重连展示执行/等待/恢复状态，失败后由玩家手动重试。

## Testing Decisions

### 测试原则与主要边界

只测试公开行为、状态与事件结果，不断言私有方法、文件排列或 React 内部组件结构。主要新增测试边界是本地冒险服务的公开操作及状态/事件输出，从最高应用层验证跨模块行为；内部继续复用现有 Harness 与规则层测试，不为每个小模块新增独立测试接缝。

用户已确认采用该边界：以本地冒险服务公开操作和事件为主，沿用 Harness/规则集成测试，以少量浏览器测试验证界面与骰子表现。

### 测试基础

现有 Agent 测试使用可控的模拟模型 Adapter、临时存档与真实规则接口，已覆盖新战斗上下文、流式工具参数、模型用量触发压缩、重试、重启重建、工具日志中断与已提交骰子不重复执行。

现有冒险会话及战斗交接测试覆盖跨进程资源账本、revision 检查、非法命令不提交、pending 决策恢复及结算稳定性。CLI 集成测试覆盖跨工作目录续玩、状态路径和机器可读错误。新增测试沿用这些方式，通过公开操作观察行为，不依赖真实模型服务计费请求。

### 必须验证的行为

1. 一条命令可启动本地服务和前端，能够创建冒险并完成叙事、战斗和叙事续接。
2. 服务事件关联到正确冒险、请求和 Agent，流式显示不把工具内部输出混成玩家故事，重连恢复状态并去重。
3. 两个 Agent 的模型和推理配置独立，更新只影响下一请求，当前请求继续使用原配置。
4. 最大输出 token 被传到模型服务，不发送 temperature / top_p，不新增输入输出合计或整轮 token 限制。
5. 主 Agent 在配置阈值触发压缩，近期工具调用与结果保持完整；完整玩家故事不丢失。
6. 战斗子 Agent 每次交接新开上下文，本场多轮历史保留，不执行压缩。
7. 修改风格指令可生效，恢复默认能还原备份，核心工具/规则指令继续存在。
8. 合法非战斗状态编辑持久化并显示记录；非法数值、战斗中编辑及过期 revision 不改变权威状态。
9. 指定怪物测试与原冒险存档隔离。
10. 希望/绝望骰可辨，动画结果与规则一致；通用动画不制造真实逐骰值，不推进随机数或重复规则行动。
11. 动画播放不阻塞后续后台处理，关闭/跳过/减少动态效果生效，历史恢复不重播。
12. 战斗行动与 pending 玩家决策节点可保存；处理中请求存档会排队，不生成中间快照。
13. 读档恢复配套规则、Agent 记忆、随机状态和故事记录，不保留未来交互；当前模型、推理与风格设置不回退。
14. 读取前备份可找回原进度，快照不复制密钥。
15. 模型失败、页面断开、重连及进程重启恢复不重复执行已提交工具/骰子，不越过仍需玩家授权的决策。
16. 48 步工具循环保护和既有请求超时按约定生效。
17. 保留并运行受影响的现有测试；浏览器验证四区布局、折叠面板、浅色阅读、设置、骰子与存读档完整流程。纯视觉细节以浏览器检查为主，不写镜像实现的测试。

## Out of Scope

- 服务器部署、多人在线、账号系统及独立桌面打包。
- 可点击的完整战斗行动/目标 UI、完整视觉演出与音频制作；第一版建立事件基础并实现骰子表现。
- 角色等级、经验、升级、地图、任务和背包等新增领域系统。
- 在战斗进行中直接编辑角色规则数值。
- 规则公式、怪物目录与角色模板的界面编辑器。
